# AI Software Factory heartbeat

Target: the one verified permanent Factory chat on the Software Factory project. Native heartbeat every 30 minutes, first PAUSED. No cron, OS scheduler or custom runner.

Activation prerequisites: native loaded coordinator/roles/skill and effective restrictive controls; current human-message provenance; complete Issue queue and actual native task ownership; worker/reviewer job binding/remote boundary proven; manual pilot accepted. Missing prerequisite means leave PAUSED or do not create schedule. File existence is not activation proof.

## Read-only observation prompt

Read FACTORY_ROOT/factory-policy.md, projects.json, .agents/skills/factory/SKILL.md and verification/acceptance.md. Observe canonical GitHub Issues/checkpoints and actual native task status only. Do not start builders or modify product, controls, permissions, Git branches or release. Preserve approval/counters. Notify only meaningful change, completion, failure or required human action; unchanged blocked state is silent. Never report unobserved controls as passed.

## Full operating prompt, enabled only after acceptance

Use the factory skill in the single verified Factory coordinator chat. Read current canonical Issue, exact version/scope and direct native human approval source; compare with actual worktree/status/SHA/native task/PR and complete portfolio queue. If an active native task exists, do not spawn a second builder. One active development package portfolio-wide. Resume current package before selecting another valid ready job by priority/order.

Validate current registry/readiness, approved plan/checks/paths/dependencies and native job-specific permissions. Routine work within valid gate 2 requires no extra plan approval. Delegate one native role at a time, independent read-only reviewer on same exact candidate. Preserve Issue human text and checkpoint; no blind overwrite on race/parse error. Increment durable repairCount before repair (max2), infraRetryCount before evidenced transient infrastructure retry (max1); restart never resets either. Read real native quota before heavy work; quota/access failure preserves checkpoint and blocks heavy work without paid fallback.

CTO 1 investment and CTO 2 changed-scope decisions await human. CTO 3 receives exact candidates/environment, actual checks/review/risk/rollback/smoke; human performs final merge/release. Persist same canonical checkpoint and real PR links; reuse PR, attach newly created PR. Notify meaningful changes/completion/failure/required action only, deduplicate repository#number|packageVersion|event|candidateSetHash-or-none. Missing human, source, enforcement or ownership produces concrete blocker; no simulated pass or permission escalation.

Notification policy is set through native tool fields. The prompt's silence rule is event deduplication, not a replacement for notification settings.
